## The Mac session (2026-08-16) — branch `m7-native-ios`

Working copy moved to a real clone at `~/biosphere`: the handoff had been unzipped from a GitHub ZIP into `~/Downloads` with no `.git`, so there was no recovery source and nowhere for `ios/` to land. Verified against `d2ba438`, both tags present, clean tree.

**Committed** — four commits on `m7-native-ios`, **none pushed**:

- `ios/` generated by `cap add ios` and committed untouched, so everything after it reads as its own diff.
- **Audio session** (§4a): `UIBackgroundModes: [audio]` plus a shim in `AppDelegate.swift` setting the `playback` category. The category is set at launch; the session deliberately is **not** activated there — sound only begins on a tap and both layers off is a supported way to use the app, so activating at launch would cut off whatever the user was already listening to. Interruptions are observed and the session reactivated on `.ended`, but only when the payload carries `.shouldResume`. Portrait-only landed here too; the generated project allowed landscape, an axis nothing here was designed against.
- **Icon and launch screen** (§5): the owner's artwork, and a launch screen that is finally dark. With no `splash.png` to work from, `@capacitor/assets` derived both appearances from the icon using its own defaults — `#ffffff` light, `#111111` dark — ignoring `capacitor.config.ts`. Since iOS serves the light variant to any device not in dark mode, the ordinary case was the white flash the background colour exists to prevent. Both are now `#05070b`, pinned in `npm run ios:assets`.
- **MAC_SETUP corrected** against what the machine actually did.

**Verified on the iOS Simulator** (iPhone 17 Pro, iOS 26.5): compiles, installs, runs. Onboarding, Enter, Home with correct wall-clock resolution, and Settings all render; portrait lock and safe-area insets correct; the built bundle carries the 8.4 MB soundtrack. IndexedDB and localStorage both work under `capacitor://localhost` — checked directly with a probe, because the boot path was briefly suspected and turned out innocent.

**Hardware verdicts (owner's iPhone 16 "DARCY", iOS 26.6, free provisioning as `com.murasxkino.biosphere.dev`):** WebKit did re-assert its own `ambient` category over the AppDelegate shim, exactly as feared — silent mode muted the app and locking killed the sound. Fixed in the engine, not the shim: on native, master routes through a MediaStreamAudioDestinationNode into a hidden `<audio>` element, so the same synthesized sound arrives as media playback and earns `playback` (AUDIO_ENGINE § Native output sink). Two further device bugs found and fixed: interruptions left the world silent until the sound toggle was flipped twice (a 2 s watchdog now automates that recovery), and the soundtrack never played — Capacitor's iOS asset handler serves media files as status-0 responses with the body intact, which the loader had been declining; it also chokes on the `?v=` cache-buster, now stripped on native. **All re-verified by ear on the device: silent switch, screen lock, hands-off call recovery, and the soundtrack in immersion — pass (2026-08-19).**

**Scene-loop profiling (DARCY, iPhone 16 @ 60 Hz, 2026-08-22)** — the M4 item that was never possible on Windows, now measured rather than felt. 10,732 frames over ~3 minutes across the app, ending on Volcanic, the heaviest scene by particle count, confirmed on screen by the owner.

| Measure | Result | ENGINEERING_GUIDE budget |
|---|---|---|
| Frame rate | **60.1 fps**, gaps pinned at 17 ms | the device's 60 Hz |
| Time inside `scene.draw` | **~1 ms typical, 4 ms worst seen** | 16.7 ms — using ~6% of it |
| Frames over 20 ms | 24 of 10,732 (**0.22%**) | — |
| Frames over 33 ms | 8 of 10,732 (**0.07%**) | — |
| Concurrent rAF loops | **1** | 1 per mounted canvas ✅ |
| Canvases mounted | **1** | ≤ 1 visible ✅ |

Measured with a profiler injected into the *built* `.app` — never `src/`, never committed — wrapping `requestAnimationFrame` to time each callback. Two caveats, both making the numbers pessimistic rather than flattering: this was a **Debug build carrying that instrumentation**, so release is faster; and WebKit coarsens `performance.now()` to ~1 ms as a Spectre mitigation, so `draw_p50 = 0` means "below timer resolution", not zero. Neither weakens the conclusion — the loop is nowhere near its budget, and **the particle ceilings need no adjustment**. Volcanic specifically ran at 60.09 fps with a 1 ms draw and zero late frames.

**§4c device matrix — walked 2026-08-22/27 on the owner's iPhone.** OS-level reduced motion: scenes go still (the rAF loop never starts) and transitions are instant — both mechanisms confirmed separately. Scroll and tap feel: correct, including long scrolls, with no whole-page rubber-band. Silent switch, backgrounding and interruptions: covered by §4a above.

One real defect found, fixed and re-verified: **long-pressing anywhere raised iOS text-selection handles**, including over the wordmark and biosphere titles. `-webkit-touch-callout: none` was working; the gap was `user-select`, applied only to buttons and icons rather than to the chrome as a whole, leaving every title and habit name selectable. The default is now inverted — the world is unselectable, the user's own words (journal notes, sealed-night reflections, and all inputs) opt back in, with a test pinning the journal opt-in. This is precisely the class of bug the device leg exists for: it reads as a `-webkit-touch-callout` question, and in a desktop browser selecting text with a mouse is normal and invisible as a defect.

Safe area: bottom and long-scroll behaviour confirmed on device; top clearance against the Dynamic Island is evidenced by the 6.9" store screenshots rather than an explicit device check — worth a glance next time the phone is in hand, though nothing has ever suggested it is wrong.
